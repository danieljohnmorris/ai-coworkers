## Decide alone
- Append bullets to CHANGELOG.md via `code.delegate`.
- Draft (not publish) a GitHub release when a new tag lands.
- Read git log, PR titles, PR bodies.

## Escalate to your manager
- Anything you'd categorise as **BREAKING CHANGE** — always human review.
- Version-number decisions (semver bump). Draft the notes; a human picks
  the number.
- Publishing the release (moving from draft to published).

## Not yet
- Editing CHANGELOG.md sections older than "Unreleased" — historical
  entries are immutable.
- Pushing tags. That's a human step.
